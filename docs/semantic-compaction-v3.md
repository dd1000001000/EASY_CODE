# Runtime-owned semantic compaction (V3)

## Scope of this change

Implements the agreed first five steps: fixed Runtime facts, semantic-only model
input, stable evidence references, durable candidate/section repair, and bounded
conservative recovery. Also fixes literal replacement in `update_file`.

The separate phase-six work is deliberately pending: historical benchmark replay,
full regression-suite migration from V2, long-task comparisons, cross-version
Resume validation, and benchmark packaging/deployment. No existing jobs are edited.

## Ownership

- Journal remains authoritative. Checkpoints do not invent snapshots or reset retry budgets.
- A transaction pins a hash-checked source prefix and a Runtime fact snapshot.
  Retired user messages are retained in full (with secret redaction), separately
  from model prose. Constraints, Plan/DAG state, unresolved commands, pending
  steering and progress experiments stay in Runtime continuity context.
- Model input is limited to current work, decisions, conclusions, hypotheses,
  failed approaches/retry conditions, and the next step. No model-authored
  `coverageCheck`, user quote/index, or evidence registry is required.
- Evidence IDs identify concrete Journal observations. Citation existence does
  not prove an interpretation; model conclusions are labelled interpretations,
  while observed status/exit-code fields are generated by Runtime.
- `manage_memory recall` supports `ev_...` and `journal_message_<index>` references
  via bounded, current-thread Runtime reads, with no RAG or tool re-execution.

## Transaction

Automatic, mandatory and explicit compaction requests use the same isolated path
for both token-based and character-only configurations. An explicit work-loop
`compact_context` call queues a semantic candidate; it does not mutate the boundary.

Only a completed prefix is eligible. The newest full phase and subsequent active
thinking/tool exchanges remain untouched. Open command handles, outstanding child
assignments and pending review/experiment work prevent retirement.

The first candidate requires `currentWork` and `nextStep`; optional sections have
empty defaults. A correction replaces only supplied top-level sections. Omitted
sections retain the saved values, including valid sections from a rejected call.
Arrays replace sections rather than append, making replay idempotent.

Journal records requests, source snapshots, attempts, raw candidates, prepared
semantic sections, rejection feedback, conservative fallback and atomic commit.
Runtime coverage checks are attached to the commit, not supplied by the model.
Failures and compactor thinking are not appended to the active work conversation.

## Failure handling

- Mechanical optional fields are filled deterministically. Required semantic
  content is not fabricated. Invalid sections get targeted feedback.
- Unknown evidence IDs get bounded repair; if repair is exhausted, structurally
  valid unsupported conclusions may be retained as unverified hypotheses.
- Retry attempts use the existing configured limit and shared model-request/Token
  budgets. Resume preserves the transaction and its consumed attempt count.
- Changed Runtime facts refresh the snapshot without resetting attempts. A response
  generated against an obsolete snapshot is discarded. A changed retired prefix
  prevents commit.
- Exhausted repair or an oversized compactor request can use a conservative
  representation: previous accepted summary, pinned Runtime facts, an exact retired
  Journal range, and the unchanged recent phase. It explicitly requires historical
  recall before relying on unavailable semantic context.
- Normal compaction targets 55% utilization. Conservative recovery may use up to
  70%, but must still save space and fit the next normal tools/system envelope.
  The summary also must fit the existing 12,000-character hard cap. If neither
  representation fits, Runtime reports `context_capacity_insufficient` and retains
  the pending transaction and raw history. It does not silently trim facts or
  mark work completed.

## Verification performed here

Production compilation/typechecking and isolated, no-provider basic checks of
normal commit, partial repair, conservative recovery, Journal recovery after an
interrupted commit, Runtime integration, unmodified recent thinking, evidence
recall and unsupported-claim demotion. These are implementation checks, not the
deferred benchmark evaluation or proof of improved pass rate.

Legacy V2 schemas/integrity helpers remain for historical data and pending test
migration; current model-facing compaction uses the V3 semantic contract.
