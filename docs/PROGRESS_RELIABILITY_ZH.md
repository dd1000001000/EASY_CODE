# 进展与上下文可靠性

[English](./PROGRESS_RELIABILITY.md)

## 命令成功不等于验证通过

CommandRuntime 分别保存进程退出码和流式框架验证结论。支持 unittest/Django、pytest、Jest 兼容摘要和 Node TAP。可归属的测试失败可以覆盖外层过滤命令的成功退出；目标混杂、缺少终态报告或解析不完整则保持 unknown。

采集发生在 EASY CODE 自己裁剪输出之前，**并非任意 Shell 管道的过滤之前**。被 grep 丢掉的信息无法恢复；必要时由主 Agent 选择最小、不丢失证据的验证，而不是 Runtime 自动重跑命令。

审计仍保留完整命令。仅能可靠识别的字面量展示管道可以排除过滤参数；测试选择参数、cwd、环境摘要和不透明控制流保持独立。失败签名使用框架失败证据，忽略无关准备日志和测试耗时；只有失败数量、没有具体失败证据时保持低置信度。仅凭 custom/smoke/unit 命令退出码不建立高置信度测试进展；build/typecheck/lint/format 等直接命令仍保留退出码合约。

## 原始测试标准

首次执行修改、命令或子 Agent 管理工具前，通过 `progress.validation.baseline` 固定当前 Thread 的测试/配置文件哈希清单；纯文件读取调查不承担扫描成本。包括用户已有未提交修改，不能用 Git HEAD 替代。验证命令比较执行前后清单与原始清单。修改/删除已有测试、改变收集配置或新增收集配置，会使结果不可直接比较；普通新增测试文件本身允许。清单扫描不完整时，不能确认验证标准未变。

完整清单只进入 Journal/Runtime，不注入模型上下文；Observation 仅携带基线摘要、比较状态和有界变化路径。只有同一目标、同一基线、可比较且高置信度的通过才能清除对应旧失败。Resume 不重置基线，新的 Thread 才建立新的原始清单。

这是针对常规测试路径/配置的有界检测，**不是断言削弱的语义证明、不可变测试执行器或完整依赖图**。单条命令内部修改后又恢复、特殊测试布局、伪造框架输出仍需要独立验证。它不直接断言作弊，不禁止合法测试修改，不自动回滚文件，也不会擅自运行原始测试副本。Reviewer 可以在原始证据充分时建议受控对照实验，仍须遵守正常命令授权。

## 调查停滞与 reviewer

保留“三个不同验证周期出现同一高置信度失败”的入口。测试标准变化是独立的审查原因，不能伪装成代码测试失败。成功的 `inspect` 命令在输出完整且足够小、可以完整计算哈希时，也参与调查证据去重；同一 commandId 的终态只计一次，等待轮询中性，截断输出不能证明完全重复。

调查监控使用带内容版本的读取覆盖范围和搜索结果标识。相同内容改变读取行号，但未增加覆盖范围，不算新增证据。默认在一个 12 次主响应窗口中，至少 5 个成功样本、重复比例超过 70% 时，要求设计区分实验；后续独立窗口仍满足条件，才可请求现有只读 reviewer。新增覆盖可以打断完全重复，但不清除 incident 或充当已验证改善。思考、耗时、没有修改、等待轮询、压缩和无关工具错误不能单独触发。未覆盖的调查工具不做自动语义停滞判断。

`progressInvestigationReviewEnabled=false` 可仅观测/提醒。窗口、比例、样本和清单容量均写入配置。没有开启自动提前终止任务。

Reviewer 复用不可变材料包和已有共享请求/Token 预算，每个 scope 最多一次审查。它不能执行命令或修改文件。新的 `run_experiment` 报告必须提供 `experimentProgram`、`experimentArgsJson`（字符串形式的 JSON 参数数组）、`experimentCwd`，以及证据、竞争解释和正反预期。这个合约只是建议，不是批准授权。Runtime 匹配实际调用，后台执行/轮询保留绑定，终态只计一次；无关命令不能代替完成实验。新错误属于新增证据，不是已验证恢复；修改测试后通过不能解除原失败。历史无命令合约的报告只能关联原验证目标。

## 压缩字段局部修复

`compactionAttempts=2`：每个事务最多一次长度纠正。主模型主动提交算第一次，不重复收费。保留第一次候选，第二次可以只补丁修改超长字段；仍超长，或纠正预算/容量不足时，对相应文本字段/条目保留前 1200 字符，不截断 UTF-16 代理对。不能转换错误类型、猜补必填项或认证无依据的结论。历史 V2 中模型填写的 Runtime 声明会丢弃，只保留经校验的语义字段。

Journal 保存原始候选、具体字段长度诊断、准备材料和确定性接受事件，再进行原子提交。摘要注明哪些字段有损截断。Resume 沿用已花次数并重放相同修复，不能买第三次提交。修复后仍检查容量和收益；不满足时走已有历史退出/最小重建降级链。RAG、Working Summary 和普通 Checkpoint 文本不能重建失败次数或重置预算。

回归覆盖包括 `command-verification`、`command`、`progress-reliability`、`progress-runtime`、`progress-lifecycle`、`compaction-transaction`，以及不调用模型 API 的真实 OS `smoke-command-usability.mjs`。
